# CMU-CFE Type Reference

A quick-reference map of the core types under `src/cfe/`: what each one
is, where it lives, and what its key members are. This is a living
document — update it whenever a type's public shape changes or a new
one is added; do not let it drift from the code. It is a reference, not
a tutorial: for the reasoning behind a design, see the relevant ADR under
`docs/adr/`.

*Covers through task 0016's checkpoint/restart addition: Phase 1's
scalar-advection solver (grid, boundary conditions, interface-value/
numerical-flux, SSP-RK2, the `ScalarAdvectionField`/`FvmSolver` split),
Phase 2's Burgers/MPI-decomposition work, Phase 3's `EulerField`,
`SlipWallBoundary`, and the vector (system) `RusanovFlux` overload, task
0011's `HllcFlux` (`docs/adr/0012-hllc-numerical-flux.md`), Phase 4's
forward-step/Shu-Osher/propagating-shock work, the PR #6 cleanup task's
(tasks/0014-pr6-cleanup.md) `cfe::abs_value` and `cfe::cartesian_fill`,
task 0015's `cfe::Index` general-purpose runtime index type
(tasks/0015-index-type.md), and task 0016's binary checkpoint/restart
format (`docs/adr/0014-checkpoint-restart-format.md`).*

## `cfe::core` — precision, indexing, host/device macros

| Type / macro | File | What it is |
|---|---|---|
| `cfe::scalar` | `core/types.hpp` | Project-wide default floating-point precision (`float` or `double`), selected at configure time via `CFE_SCALAR_TYPE`. Most code is templated on `Scalar` directly rather than using this alias, so both precisions can be exercised in one build. |
| `cfe::Index` | `core/types.hpp` | `std::size_t`. The general-purpose runtime index/count/offset type (task 0015) -- buffer offsets, element counts, flat-index results, `Backend::run` iteration indices, loop variables. A plain alias (same width/signedness as `std::size_t`, zero-cost), the same precedent `cfe::scalar` established. **Not** a replacement for `local_index`/`global_index` below, which remain narrower-purpose partition-local/distributed index types. Does not apply to non-type template parameters that are compile-time arity/dimension constants (`N`/`NComponents`/`Dim` in `FixedArray`/`Field`/`FvmSolver`/etc.), which stay `std::size_t` -- see `tasks/0015-index-type.md` for the full scope rule. |
| `cfe::local_index` | `core/types.hpp` | `std::int32_t`. Within-partition/rank indices. |
| `cfe::global_index` | `core/types.hpp` | `std::int64_t`. Indices that may need to address a distributed problem larger than 2^31 elements. |
| `cfe::Axis` | `core/types.hpp` | `{X=0, Y=1, Z=2}`. Lives in `core/` (not `grid/`) so numerics code (`numerics/numerical_flux/upwind.hpp`) can use it without depending on the grid module. Values are stable so `static_cast<Index>(axis)` indexes a per-axis `Vector`/`FixedArray` directly. |
| `cfe::Side` | `core/types.hpp` | `{Low, High}`. |
| `CFE_HOST_DEVICE`, `CFE_DEVICE`, `CFE_HOST`, `CFE_GLOBAL` | `core/macros.hpp` | Expand to `__host__ __device__` / `__device__` / `__host__` / `__global__` when compiled by `nvcc` (`__CUDACC__` defined), and to nothing otherwise. **The only place any code may know whether it's being compiled by nvcc** — physics/numerics code must use these macros, never raw CUDA attributes. |
| `CFE_FORCEINLINE` | `core/macros.hpp` | `__forceinline__` under nvcc, `inline __attribute__((always_inline))` under GCC/Clang, plain `inline` otherwise. |
| `cfe::ComponentCounts` | `core/component_counts.hpp` | `std::index_sequence<1,5,10,20,50,100>` — the required component-count sweep (AGENTS.md #8). |
| `cfe::for_each_component_count(f)` | `core/component_counts.hpp` | Calls `f(std::integral_constant<std::size_t, N>{})` once per required `N`. `f` must be a generic (`auto`-parameter) lambda; if it launches CUDA work, the body must call out to a separate template function rather than define the extended `__device__` lambda directly inside the generic lambda — nvcc rejects that (see `agent_history.md`, 2026-09-08 entry). |

## `cfe::math` — fixed-size containers and operations

| Type / function | File | What it is |
|---|---|---|
| `cfe::FixedArray<Scalar, N>` | `math/fixed_array.hpp` | Allocation-free, trivially-copyable `Scalar[N]`. The one building block for scalars, vectors, and physics states. `operator[]`, `data()`, `+=`/`-=`/`*=`/`/=`. |
| `cfe::ScalarValue<Scalar>` | `math/fixed_array.hpp` | Alias for `FixedArray<Scalar, 1>`. |
| `cfe::Vector<Scalar, Dim>` | `math/fixed_array.hpp` | Alias for `FixedArray<Scalar, Dim>`. |
| `cfe::State<Scalar, NComponents>` | `math/fixed_array.hpp` | Alias for `FixedArray<Scalar, NComponents>` — a full per-cell physics state. |
| `operator+`, `operator-`, `operator*`, `operator/`, `componentwise_multiply` | `math/operations.hpp` | Componentwise arithmetic on `FixedArray`. |
| `cfe::contract(a, b)` | `math/operations.hpp` | Full contraction to a scalar: `sum_k a[k]*b[k]` (generalized dot product). |
| `cfe::weight(a, w)` | `math/operations.hpp` | Componentwise scaling of `a` by `w`; returns a `FixedArray`, not a scalar (unlike `contract`). |
| `cfe::abs_value<Scalar>(x)` | `math/scalar_ops.hpp` | Host/device absolute value, `x < 0 ? -x : x`. Added (PR #6 cleanup task) to collect five independent hand-rolled copies of this exact ternary (`BurgersField`/`EulerField::wave_speed`, both `rusanov_flux` overloads, `BlockInterfaceBoundary::detail::close`) into one primitive. Named `abs_value`, not `abs`, to avoid colliding with `std::abs`'s mixed integer/floating-point overload set. |

## `cfe::field` — contiguous storage

| Type | File | What it is |
|---|---|---|
| `cfe::AoSLayout`, `cfe::SoALayout` | `field/layout.hpp` | Index policies: `index(cell, component, n_cells, n_components)`. AoS = `cell*n_components+component` (grouped by cell); SoA = `component*n_cells+cell` (grouped by quantity). No common base class — duck-typed, matching `BoundaryCondition`'s style. Per ADR 0002: AoS is the CPU default, SoA the CUDA default (measured, not assumed). |
| `cfe::Field<Scalar, NComponents, Layout=AoSLayout>` | `field/field.hpp` | Owning host-side storage: one `std::vector<Scalar>` sized `n_cells*NComponents`, allocated once in the constructor. `operator()(cell, component)`, `view()`/`view() const`. |
| `cfe::FieldView<Scalar, NComponents, Layout>` | `field/field.hpp` | Non-owning, trivially-copyable pointer + `n_cells`. Safe to capture by value into a `CFE_DEVICE` lambda. Equally valid over host or device memory — this is what makes grid/boundary/numerics code backend-agnostic. |
| `cfe::backend::cuda::DeviceField<Scalar, NComponents, Layout>` | `backend/cuda/device_field.cuh` | Device-memory counterpart to `Field`. `copy_from_host`/`copy_to_host`, `view()` returns the *same* `FieldView` type CPU code uses. `.cu`-only. |
| `cfe::BlockSet<Scalar, NComponents, Layout=AoSLayout>` (Phase 4) | `field/block_set.hpp` | Owning storage for a block-structured grid's several same-kind buffers (e.g. the forward-facing-step's two `CartesianGrid` blocks, ADR 0011): ONE `std::vector<Scalar>` sized for the sum of every block's cell count, built from `explicit BlockSet(std::initializer_list<cfe::Index> block_cell_counts)`. `view(block)`/`view(block) const` return a `FieldView`/`FieldView<const Scalar,...>` at that block's precomputed offset into the shared allocation — block `b+1`'s region starts immediately after block `b`'s, so consecutive blocks are genuinely contiguous, not just independently allocated with equal values (verified by `tests/unit/test_forward_step_sanity.cpp`'s `test_forward_step_block_set_buffers_are_genuinely_one_contiguous_allocation`). Needs no `FvmSolver`/`BoundaryCondition`/time-integration changes to use: every consumer of a `Field`-provided `FieldView` already treats it as a plain pointer+count with no ownership assumption, so a `BlockSet`-provided `FieldView` is indistinguishable to them. See `ARCHITECTURE.md` #21. |

## `cfe::backend` — execution abstraction

| Type / function | File | What it is |
|---|---|---|
| `cfe::parallel_for(n, f)` | `backend/parallel_for.hpp` | Alias for whichever CPU backend is the project default (`CFE_DEFAULT_BACKEND`); the backend-agnostic call site physics/numerics code should use. |
| `cfe::backend::serial::parallel_for(n, f)` | `backend/cpu/serial.hpp` | Plain sequential `for` loop, `f(i)` for `i` in `[0,n)`. |
| `cfe::backend::threaded::parallel_for(n, f, n_threads=0)` | `backend/cpu/threaded.hpp` | Static contiguous chunking across `std::thread`s. No persistent pool — spawns fresh threads every call (documented cost, see ADR 0001). |
| `cfe::backend::cuda::parallel_for(n, f, block_size=256)` | `backend/cuda/cuda_backend.cuh` | One GPU thread per index. **Asynchronous** — returns once the launch is queued, does not wait for completion. `.cu`-only; call explicitly, never through the `cfe::parallel_for` alias. |
| `cfe::backend::cuda::synchronize()` | `backend/cuda/cuda_backend.cuh` | Blocks until all queued device work completes. Required before reading a `parallel_for` result on the host, or before ending a timed region. |
| `cfe::CpuParallelFor` / `cfe::CudaParallelFor` | `backend/parallel_for.hpp` / `backend/cuda/cuda_backend.cuh` (CUDA-only) | Backend-selection tags: `Backend::run(n, f)` calls `cfe::parallel_for`/`cfe::backend::cuda::parallel_for` respectively. This is what lets kernel-launching code (grid/boundary conditions, `FvmSolver`, `ssp_rk2_step`) be written once and work on either backend via a `Backend` template parameter (default `CpuParallelFor`), instead of duplicating the logic per backend the way Phase 0's much simpler kernels did. `CudaParallelFor::run` does not call `synchronize()` itself — every kernel goes to the default stream, so CUDA's in-order-per-stream guarantee keeps a dependent launch sequence correct without it; the caller still must synchronize before reading a result on the host. |
| `CFE_CUDA_CHECK(expr)` | `backend/cuda/cuda_check.cuh` | Throws `std::runtime_error` with file/line/`cudaGetErrorString` on any non-`cudaSuccess` CUDA API result. Every `cudaMalloc`/`cudaMemcpy`/launch-error-check in this codebase goes through this. |
| `cfe::backend::mpi::Environment` (Phase 2, `CFE_ENABLE_MPI`-gated) | `backend/mpi/mpi_environment.hpp` | RAII `MPI_Init_thread(MPI_THREAD_FUNNELED)`/`MPI_Finalize` guard, constructed once at the top of `main()`; throws `std::runtime_error` if the local MPI implementation cannot provide at least `MPI_THREAD_FUNNELED` (needed so the threaded CPU backend can run worker threads for per-cell kernels while only the initializing thread ever calls MPI). `rank(comm=MPI_COMM_WORLD)`/`size(comm=MPI_COMM_WORLD)` free functions alongside it. |
| `cfe::backend::mpi::mpi_datatype_for<Scalar>()` (Phase 2, `CFE_ENABLE_MPI`-gated) | `backend/mpi/mpi_datatype.hpp` | Maps `float`/`double` to `MPI_FLOAT`/`MPI_DOUBLE`. Only those two are specialized — an unsupported `Scalar` fails to compile. |
| `cfe::backend::mpi::allreduce_max<Scalar>(local_value, comm=MPI_COMM_WORLD)` (Phase 2, task 0006, `CFE_ENABLE_MPI`-gated) | `backend/mpi/mpi_reduce.hpp` | Thin wrapper over `MPI_Allreduce(..., MPI_MAX, ...)` — every rank gets the same (global) maximum back. Needed by any state-dependent-CFL field (e.g. `BurgersField`'s `max|u|`-based `dt`): call once after computing a rank-local reduction, before sizing a shared timestep, or different ranks can pick different `dt`/step counts for the same nominal run — confirmed to hang (not just mis-time) a decomposed Burgers run when skipped, see ADR 0009. |

## `cfe::grid` — Cartesian grid, boundary conditions, ghost cells (Phase 1-3)

| Type / function | File | What it is |
|---|---|---|
| `cfe::CartesianGrid<Scalar>` | `grid/structured/cartesian_grid.hpp` | Describes one block: real cell counts, ghost-layer depth (`Index`), and spacing (`dx`/`dy`/`dz`, type `Scalar`) per dimension, plus interior origin. Templated on `Scalar` (not hardcoded `double`) so a `float`-precision solver carries no hidden conversion for its grid spacing. `flat_index(i,j,k)` is the *only* place `(i,j,k)` becomes the flat `cell` index `Field`/`FieldView` expect — ghost cells live in the same contiguous array as real cells, at padded indices outside `[n_ghost, n_ghost+n_cells)`. Spacing/extents are scoped to this one object (not global) so a second block at a different resolution — fixed-block AMR — doesn't require redesigning this type. |
| `cfe::cartesian_fill<Axis, Backend=CpuParallelFor>(grid, transform)` (PR #6 cleanup task) | `grid/boundary/cartesian_fill.hpp` | The shared ghost-fill iteration skeleton every axis-aligned `BoundaryCondition::fill_x/fill_y/fill_z` below needs: decodes a flat index into `(g, o1, o2)` (`g` = position within the ghost layer, `o1`/`o2` = the other two axes' padded indices, same `if constexpr`-dispatched convention `MpiHaloBoundary::exchange<Axis>` already established) and dispatches one `Backend::run` call over it. `transform(g, o1, o2)` — an ordinary host/device-callable lambda supplied at each `fill_x`/`fill_y`/`fill_z` call site — owns everything specific to one `BoundaryCondition` type (how many source indices to compute, any sign flip, any neighbor-validity branching); this function has no notion of boundary physics beyond the decode. Used by `PeriodicBoundary`/`StaticBoundary`/`InflowOutflowBoundary`/`SlipWallBoundary` for their whole body, and by `BlockInterfaceBoundary` for just this decode/dispatch (its neighbor-read branching stays local — not forced into the same callback shape). Does not touch `MpiHaloBoundary`, which packs/exchanges/unpacks whole slabs across MPI ranks, a different problem already unified on its own terms. All indices (`g`/`o1`/`o2`, and `ghost_depth`/`p_o1`/`p_o2` internally) are `Index` (task 0015). |
| `cfe::PeriodicBoundary` | `grid/boundary/boundary_condition.hpp` | Wraps one axis's ghost layer from the opposite real boundary. `fill_x<Backend=CpuParallelFor>`/`fill_y<...>`/`fill_z<...>`, each a thin call into `cartesian_fill<Axis>` passing its own per-component transform. `Backend` is the *first* template parameter (Scalar/N/Layout are deduced from the `FieldView` argument after it), specifically so `fill_ghost_cells` can override just `Backend` explicitly. Stateless. |
| `cfe::StaticBoundary<Scalar, N>` | `grid/boundary/boundary_condition.hpp` | Writes a fixed `State<Scalar,N>` into every ghost cell on the low/high side of one axis (the two sides may differ). Same `fill_x<Backend>`/`fill_y<Backend>`/`fill_z<Backend>` shape as `PeriodicBoundary` — duck-typed, no common base (AGENTS.md #12: no virtual functions inside kernels). |
| `cfe::InflowOutflowBoundary<Scalar, N>` (Phase 2) | `grid/boundary/boundary_condition.hpp` | Fixed Dirichlet (`inflow_value`) on the low end of one axis, zero-order extrapolation (copies the single nearest real cell into every ghost layer on that end) on the high end. Same `fill_x`/`fill_y`/`fill_z` shape as the other two. First real implementation of AGENTS.md #17's named "extrapolation/outflow" BC category — explicitly the simple zero-order kind, not the characteristic-based partial-specification version AGENTS.md reserves for Phase 3's compressible Euler work. Added for `tutorials/burgers_1d_shock_and_steepening/`'s moving-shock case. |
| `cfe::fill_ghost_cells<Scalar,N,Layout,Boundary,Backend=CpuParallelFor>(field, grid, axis, boundary)` | `grid/ghost/ghost_fill.hpp` | The single call site solver code uses to fill ghost cells. This is the actual swappable seam: solver code never touches `(i,j,k)±1` indexing directly, so a future MPI halo-exchange or coarse-fine-AMR-interpolation provider is a new `boundary` type at this same call shape, not a redesign. Forwards `Backend` to `boundary.template fill_x<Backend>(...)` etc. Note: this one function is instantiated per `Boundary` type with a runtime `switch` over all three axes, so any `Boundary` passed to it at all must implement `fill_x`/`fill_y`/`fill_z` — even a 2D-only type whose `fill_z` is never reached at runtime still needs one that compiles (see `tutorials/burgers_2d_diagonal_shock/burgers_2d.cpp`'s `DiagonalShockExactBoundary` for a worked example of this gotcha). |
| `cfe::SlabPartition` / `cfe::make_slab_partition(global_nx, rank, size, periodic)` (Phase 2, task 0004) | `grid/partition/slab_partition.hpp` | 1D slab decomposition along X: splits `global_nx` cells across `size` ranks (remainder-to-the-first-ranks rule), returning each rank's `local_nx`, `global_offset_x`, and `left_rank`/`right_rank` neighbors (`kNoNeighbor = -1` for a true physical boundary, or periodic wraparound). Pure index arithmetic, no MPI dependency — unit-testable without an MPI toolchain. See ADR 0009. |
| `cfe::CartesianPartition` / `cfe::make_cartesian_partition(global_nx, global_ny, global_nz, px, py, pz, rank, size, periodic_x, periodic_y, periodic_z)` (Phase 2, task 0005) | `grid/partition/cartesian_partition.hpp` | Full 3D block decomposition: calls `make_slab_partition` once per axis for each axis's local extent/offset, plus computes 6 face-neighbor ranks (`x_left_rank`/`x_right_rank`/`y_left_rank`/`y_right_rank`/`z_left_rank`/`z_right_rank`, same `kNoNeighbor` sentinel). `px*py*pz` must equal `size` — caller-chosen process-grid shape, no auto-factoring in this type. No diagonal/corner neighbors computed — not needed for this solver's axis-split stencil (see ADR 0009's amendment). Pure index arithmetic, no MPI dependency. |
| `cfe::MpiHaloBoundary<Scalar, N>` (Phase 2, task 0004/0005, `CFE_ENABLE_MPI`-gated) | `grid/boundary/mpi_halo_boundary.hpp` | Same `fill_x`/`fill_y`/`fill_z` shape as the other boundary types. One instance handles exactly one axis's neighbor pair (constructor takes `(MPI_Comm, left_rank, right_rank)` directly — not a whole partition object), so the same type is constructed three times (once per axis, pulling each pair from a `SlabPartition` or `CartesianPartition`) and plugged in as `BoundaryX`/`BoundaryY`/`BoundaryZ` simultaneously via explicit aggregate construction. All three fill methods are real (task 0005 generalized away task 0004's X-only throwing Y/Z stubs), sharing one `if constexpr`-dispatched private `exchange<Axis>` helper. Blocking `MPI_Sendrecv`, two calls per exchange. Buffers sized once per grid shape, never shrunk. On a side with no neighbor (`MPI_PROC_NULL`, a non-periodic domain's true physical edge), the unpack step leaves that side's ghost cells untouched (whatever was already there is preserved) rather than overwriting them with a stale/zero receive buffer; it does not compose with another boundary to give that edge a real value itself. See ADR 0009. |
| `cfe::SlipWallBoundary<Field>` (Phase 3) | `grid/boundary/slip_wall_boundary.hpp` | Reflecting ("slip wall") BC: mirrors real-cell values into the ghost layer, negating only the single momentum component normal to the wall (`Field::momentum_index(axis)`) — density/energy/tangential-momentum copy unchanged. CFE's first Field-aware `BoundaryCondition` (AGENTS.md #17, ARCHITECTURE.md #11): unlike every other type in this table, it needs to know which raw component index means "normal momentum" for the `Field` in play, so it is templated on `Field` and calls its static `momentum_index(Axis)` rather than hardcoding an index. The *lighter-weight* Field-aware shape (a static lookup + sign flip) — not the characteristic-based partial-specification subsonic inflow/outflow BC ARCHITECTURE.md #11 also describes (still unimplemented; needs an equation of state and wave-speed evaluation). Same `fill_x`/`fill_y`/`fill_z` shape as every other boundary type; works for any `Field` exposing `momentum_index`, not Euler-specific by name. See ADR 0010. |

| `cfe::BlockInterfaceBoundary<Scalar, Field, InterfaceSide, Layout=AoSLayout>` (Phase 4, task 0010) | `grid/boundary/block_interface_boundary.hpp` | Same-process cross-block ghost-fill BoundaryCondition: fills one block's X-axis ghost layer by reading a neighbor `CartesianGrid`/`FieldView` directly (same process, no MPI, no copy buffer — the same-process analogue of `MpiHaloBoundary`'s cross-partition read) wherever the two blocks share physical height (`j_valid_lo <= j < j_valid_hi`), and falls back to a local slip-wall-style mirror (same formula `SlipWallBoundary` uses, Field-aware via `Field::momentum_index`) where they don't — the forward-facing-step's own riser face. `InterfaceSide` (`cfe::Side`, `core/types.hpp`) picks which end of this block's X axis is the interface; the OTHER end is a fixed value (`Side::High`, the "upstream" block's own tunnel inlet) or zero-order-extrapolated (`Side::Low`, the "downstream" block's own outlet) — see `docs/adr/0011-forward-step-block-interface.md` for why that pairing, not a fully independent 2x2 combination. Same `fill_x`/`fill_y`/`fill_z` duck-typed shape as every other `BoundaryCondition` (`fill_y`/`fill_z` throw — this type is only ever used as `BoundaryX`). Requires both blocks to share identical `dy`/`dz`/`nz`/`ngz` (checked once per `fill_x` call, not per cell) so cells line up 1:1 with no interpolation — what makes the cross-block flux agreement `tests/verification/test_forward_step_interface_conservation.cpp` checks exact rather than approximate. |

## `cfe::numerics` — interface reconstruction and flux combinator (Phase 1-3)

Physics-agnostic by design: none of these know what PDE they're being used
for. The physics lives in `cfe::fields` instead (below).

| Type / function | File | What it is |
|---|---|---|
| `cfe::fvm::interface_value_right(state_left, state_self, state_right)` / `cfe::fvm::interface_value_left(...)` | `numerics/fvm/interface_value.hpp` | This cell's own value at its `+axis`/`-axis` face: central-difference linear extrapolation (`state_self ± (state_right - state_left)/4`), using only its immediate ("1-ring") neighbors. Together, the FVM implementation of "produce my value at a face from my own representation" — a future DG element could implement the same shape from its own internal DOFs instead. |
| `cfe::fvm::CentralDifferenceReconstruction` | `numerics/fvm/interface_value.hpp` | Stateless functor wrapping the two functions above into the `.right(...)`/`.left(...)` shape `FvmSolver` is generic over (its default `Reconstruction`). Oscillates (Gibbs-type overshoot/undershoot) next to a genuine discontinuity — not shock-safe; see `MusclMinmodReconstruction` below for that. |
| `cfe::fvm::FirstOrderReconstruction` (Phase 2) | `numerics/fvm/first_order_reconstruction.hpp` | Piecewise-constant: `.right(...)`/`.left(...)` both just return the cell's own value, ignoring both neighbors. The simplest, most diffusive member of the `Reconstruction` family — used as the explicit baseline Burgers' shock-capturing tutorials compare `MusclMinmodReconstruction` against, not as a preferred production scheme. |
| `cfe::fvm::minmod(a, b)` | `numerics/fvm/muscl_minmod.hpp` | The minmod slope limiter: `0` if `a`/`b` disagree in sign (or either is exactly zero), otherwise whichever of the two is smaller in magnitude (shared sign). The TVD (total-variation-diminishing) building block everything below is built on. Uses direct sign comparisons, not the textbook `a*b<=0` test -- that product underflows to exactly `0` for small-but-equal-magnitude same-sign inputs well before either operand itself underflows (e.g. `1e-200*1e-200` in `double`), which would wrongly clip a real, representable slope to zero. |
| `cfe::fvm::muscl_minmod_slope/value_right/value_left(state_left, state_self, state_right)` | `numerics/fvm/muscl_minmod.hpp` | MUSCL (van Leer, 1979) reconstruction with the minmod limiter: this cell's slope is `minmod(state_self-state_left, state_right-state_self)`; its two face values are `state_self ± slope/2`. Unlike `CentralDifferenceReconstruction`'s unconditional slope, this clips to exactly zero at a local extremum or discontinuity — what makes it non-oscillatory (TVD) next to a shock, at the cost of being the most diffusive limiter in its family and reducing to 1st order at smooth extrema (an accepted, documented property of TVD limiters, not a bug — see `docs/adr/0008-...md`). |
| `cfe::fvm::MusclMinmodReconstruction` | `numerics/fvm/muscl_minmod.hpp` | Stateless functor wrapping the three functions above into the same `.right(...)`/`.left(...)` shape `CentralDifferenceReconstruction` uses — a second, additive `Reconstruction`, substituted as a template argument with zero `FvmSolver` changes. `BurgersField`'s paired shock-capturing reconstruction (see `docs/adr/0008-burgers-shock-capturing-scheme.md` for why minmod specifically, versus superbee/van Leer/MC or WENO). |
| `cfe::upwind_flux(left_value, right_value, axis, field)` / `cfe::UpwindFlux` | `numerics/numerical_flux/upwind.hpp` | Combines two independently-computed face values into one flux by upwind selection on the sign of `field.wave_speed(left_value, right_value, axis)`, then evaluates `field.physical_flux(...)` on the upwind side. Never knows what those two Calculator methods actually compute — that's `Field`'s job. Switches on `wave_speed`'s *sign*, so it expects a signed value (e.g. `ScalarAdvectionField`'s velocity) — not entropy-correct for a genuinely nonlinear flux like Burgers' at a sonic/transonic point; see `RusanovFlux` below for that case. |
| `cfe::rusanov_flux(left_value, right_value, axis, field)` / `cfe::RusanovFlux` (Phase 2; vector overload Phase 3) | `numerics/numerical_flux/rusanov.hpp` | Local Lax-Friedrichs: `0.5*(F(uL)+F(uR)) - 0.5*|alpha|*(uR-uL)`, `alpha = field.wave_speed(uL,uR,axis)` — **always takes `|alpha|`**, deliberately, since `Field::wave_speed(...)` is not contractually non-negative (`ScalarAdvectionField`'s is signed; `BurgersField`'s/`EulerField`'s already are). Entropy-satisfying for any convex scalar flux, which is what makes it valid for `BurgersField` specifically (`UpwindFlux` is not, at a sonic point). Same `operator()(left, right, axis, field)` shape as `UpwindFlux`; `FvmSolver`'s default `NumericalFlux` is still `UpwindFlux`, so using `RusanovFlux` is an explicit template-argument choice. **Phase 3 addition:** both the free function and the functor now also have a `State<Scalar,N>`-in/-out overload, selected by argument type, for multi-component (system) Fields like `EulerField` — `alpha` is computed ONCE from the full states and shared across every component's dissipation term (the correct system generalization, not N independent scalar problems). Same formula, same type, no change to the N=1 scalar overload. |
| `cfe::hllc_flux(left_state, right_state, axis, field)` / `cfe::HllcFlux` (task 0011) | `numerics/numerical_flux/hllc.hpp` | Toro/Spruce/Speares HLLC approximate Riemann solver: a 3-wave (`S_L`,`S_star`,`S_R`) construction that resolves the contact discontinuity as a genuine jump at its own speed, unlike Rusanov's single dissipative wave. `S_star`-dependent star-region conserved state is generalized over `Dim` via `Field::momentum_index(axis)` (only the NORMAL momentum component takes the star velocity; every tangential component is carried through density-rescaled at its original velocity). Wave-speed estimate: Toro's ANRS (adaptive PVRS/TRRS/TSRS) used only as a seed, refined by a FIXED, unconditional 5 Newton-Raphson iterations toward the exact two-shock/two-rarefaction `p*` (GPU-warp-uniform by construction — see `docs/adr/0012-hllc-numerical-flux.md` for why the non-iterative seed alone produced a silent, severe bug: a wrong-signed `S_L` at a strong Mach-3 wall reflection, reducing the flux to the unperturbed physical flux with zero dissipation). **Not a generic drop-in `NumericalFlux`** the way `RusanovFlux` is: needs `field.density/pressure/velocity_component/sound_speed/gamma` and `Field::momentum_index/energy_index` (a full ideal-gas EOS), so it only compiles against `EulerField` (or any future Field exposing the same Calculator surface), not `BurgersField`/`ScalarAdvectionField`. Same `operator()(left_state, right_state, axis, field)` functor shape as `RusanovFlux`'s vector overload — drop-in for `FvmSolver`'s `NumericalFlux` template slot with zero solver changes. `cfe::detail::hllc_wave_speeds`/`cfe::detail::HllcWaveSpeeds` expose the three wave speeds directly (used by `tests/unit/test_hllc_flux.cpp` to avoid a duplicated copy of the arithmetic in its exact-solver cross-checks). |

## `cfe::fields` — the physics (Phase 1-3)

Where the physics-specific Calculator functions actually live (ARCHITECTURE.md
#2's "Field" concept), kept separate from the physics-agnostic numerics above.

| Type | File | What it is |
|---|---|---|
| `cfe::ScalarAdvectionField<Scalar, Dim>` | `fields/scalar_advection/field.hpp` | The linear scalar-advection equation `dQ/dt + velocity·grad(Q) = 0`. Holds a `Vector<Scalar, Dim>` velocity (one component per active axis — a 1D problem uses `Dim=1`, 2D uses `Dim=2`, etc.) and provides the two Calculator methods `NumericalFlux` needs: `physical_flux(state, axis) -> velocity[axis]*state` and `wave_speed(state_left, state_right, axis) -> velocity[axis]` (**signed** — designed for `UpwindFlux`'s sign-based direction selection, not a magnitude; pairing this `Field` with `RusanovFlux` relies on `RusanovFlux` taking `|wave_speed(...)|` itself, not on this method returning a non-negative value). Exposes `static constexpr std::size_t dim = Dim` so `FvmSolver` can select 1D/2D/3D behavior with `if constexpr` at compile time rather than a per-cell runtime check. |
| `cfe::BurgersField<Scalar, Dim>` (Phase 2) | `fields/burgers/field.hpp` | The inviscid Burgers equation `dQ/dt + div(F(Q)) = 0`, `F(Q) = Q^2/2` — this codebase's first genuinely nonlinear conservation law (smooth initial data can steepen into a real shock in finite time; `ScalarAdvectionField` only ever translates its initial profile unchanged). No `velocity` member: the nonlinearity is self-advecting (`F'(Q) = Q`), so `physical_flux`/`wave_speed` depend only on the state values passed in. `wave_speed(state_left, state_right, axis) -> max(|state_left|,|state_right|)` — **always non-negative** (a different role than `ScalarAdvectionField`'s own signed `wave_speed`): the local maximum characteristic speed `RusanovFlux` needs as its dissipation coefficient. Supplies its own Calculator methods under this same `(state, axis)`-in shape with zero `FvmSolver` interface changes (exactly as `ScalarAdvectionField`'s own header comment anticipated). `n_components = 1` (added in Phase 3 when `FvmSolver` was generalized over `Field::n_components` to host `EulerField`; no change to this Field's own physics). Paired with `MusclMinmodReconstruction`/`RusanovFlux`, not `CentralDifferenceReconstruction`/`UpwindFlux` (see `docs/adr/0008-burgers-shock-capturing-scheme.md`). |
| `cfe::EulerField<Scalar, Dim>` (Phase 3) | `fields/euler/field.hpp` | The compressible Euler equations for a calorically-perfect gamma-law gas: `dQ/dt + div(F(Q)) = 0`, `Q = (density, momentum[Dim], total_energy)`, `n_components = Dim+2`. CFE's **first genuinely multi-component Field** — unlike `ScalarAdvectionField`/`BurgersField` (`n_components=1`), its Calculators (`physical_flux`, `wave_speed`) take/return full `State<Scalar, n_components>` vectors, since any one component's flux depends on the whole state (e.g. mass flux `rho*u` needs `u=momentum/density`). `gamma` (default 1.4) is a runtime data member, not a template parameter. Semantic accessors: `density`/`momentum`/`total_energy`/`velocity_component`/`kinetic_energy`/`pressure` (ideal-gas EOS `p=(gamma-1)*(E-KE)`)/`sound_speed`. `wave_speed(stateL, stateR, axis) -> max(|u_axis|+c)` across both states — the single non-negative Rusanov dissipation coefficient. `static constexpr Index momentum_index(Axis)` / `energy_index()` expose this Field's own conserved-component layout so other code (`SlipWallBoundary<Field>`) can look it up instead of hardcoding indices. `conserved_from_primitive(density, velocity, pressure)` is a host-only IC/BC convenience. Paired with `MusclMinmodReconstruction` (componentwise, not characteristic — see `docs/adr/0010-...md`) and `RusanovFlux`'s vector overload; verified against the Sod shock tube's exact solution (`tests/verification/test_euler_sod_shock_tube.cpp`). |

## `cfe::solver` — orchestration, no physics (Phase 1-3)

| Type / function | File | What it is |
|---|---|---|
| `cfe::ssp_rk2_step<Scalar, FieldViewT, Residual, Backend=CpuParallelFor, IndexMap=IdentityIndexMap>(state, stage1, residual_scratch, dt, residual, n_active, index_map=IndexMap{})` | `solver/time_integration/ssp_rk2.hpp` | Advances `state` in place by one SSP-RK2 (Heun's method) step. Generic over a `residual(state_in, out)` callable computing `out := dQ/dt`; has no knowledge of what a "ghost cell" is, only of an opaque `index_map(r) -> storage index` for `r` in `[0, n_active)` — its combine kernels visit *only* those `n_active` indices, matching standard FVM practice (fill ghosts -> compute residual on interior cells -> integrate interior cells only); ghost cells are never read or written by the combine step itself (`FvmSolver::residual()` still fills them, via its own `fill_ghost_cells` calls, independently). `stage1`/`residual_scratch` are caller-allocated scratch storage of the *same full (padded) shape* as `state`, reused every call — their size does not change based on `n_active`; only which indices get visited does. `Scalar`/`FieldViewT`/`Residual` are deducible from arguments; to run on CUDA, all four of `Scalar`/`FieldViewT`/`Residual`/`Backend` must be given explicitly (`Backend` isn't deducible and isn't first in the list here, unlike `fill_x`/`y`/`z` below) — `IndexMap` remains deducible from the `index_map` argument even then. **Phase 4 (task 0010):** now a thin wrapper calling `ssp_rk2_combine_stage1`/`ssp_rk2_combine_stage2` (below) around its own two `residual(...)` calls — same formula, same behavior, no change for any existing caller. |
| `cfe::ssp_rk2_combine_stage1<Scalar, FieldViewT, Backend=CpuParallelFor, IndexMap=IdentityIndexMap>(state, stage1, residual_scratch, dt, n_active, index_map=IndexMap{})` / `cfe::ssp_rk2_combine_stage2<...>(...)` (Phase 4, task 0010) | `solver/time_integration/ssp_rk2.hpp` | `ssp_rk2_step`'s own two internal combine formulas (`stage1 := state + dt*residual_scratch`; `state := 0.5*state + 0.5*(stage1 + dt*residual_scratch)`), pulled out as their own public, `Backend`-generic, `CFE_HOST_DEVICE`-kernel functions — unlike `ssp_rk2_step`, neither calls `residual` itself, so a caller can compute several solvers' own residuals first (in whatever order a coupling needs) and then combine each one's stage separately. Needed by a same-process multi-solver coupling that must do something *between* a stage's residual-then-combine (e.g. re-point a cross-block `BoundaryCondition`'s neighbor read at the other solver's freshly-written stage-1 buffer) — see `grid/boundary/block_interface_boundary.hpp` and `tests/verification/forward_step_setup.hpp::ForwardStepBlocks::step()`, which calls these two directly, once per block, interleaved with that re-pointing. |
| `cfe::IdentityIndexMap` | `solver/time_integration/ssp_rk2.hpp` | `ssp_rk2_step`'s default `IndexMap`: `operator()(r) -> r`. Correct whenever there is no grid at all (e.g. integrating a plain ODE system with a single-component, no-ghost `Field`), which is why `ssp_rk2_step` can still be used without a grid in play. |
| `cfe::FvmSolver<Scalar, Layout, Field, BoundaryX, BoundaryY=BoundaryX, BoundaryZ=BoundaryX, Reconstruction=fvm::CentralDifferenceReconstruction, NumericalFlux=UpwindFlux, Backend=CpuParallelFor>` | `solver/explicit/fvm_solver.hpp` | Assembles a flux-form residual for a conservation law, generic over `Field::n_components` (Phase 3: generalized from a hardcoded single-component assumption to host multi-component Fields like `EulerField` — see ADR 0010; `if constexpr (N==1)` keeps the exact pre-existing call path, bit-for-bit, for every N=1 Field). Dimension-agnostic: the residual loop and ghost-fill both run over however many axes are active, decided at compile time from `Field::dim` (`if constexpr`, not a per-cell runtime branch) — an orthogonal compile-time axis of genericity from component count. Contains no physics itself — only orchestrates `Field` (physics), `Reconstruction`+`NumericalFlux` (numerics), and `BoundaryX`/`Y`/`Z` (ghost-cell filling), calling only their public interfaces; reconstruction is always componentwise (each component independently), never characteristic. Requires `grid.ngx/ngy/ngz >= 2` on every active axis (each cell's residual needs both its faces, and each face's two one-sided reconstructions each reach one cell further out). Pass `Backend=CudaParallelFor` (as the last template argument) to run on CUDA. Exposes `active_cell_count()` (`-> grid.nx*grid.ny*grid.nz`) and `active_cell_index_map()` (`-> detail::CartesianRealCellIndexMap<Scalar, Field::dim>{grid}`) specifically to be passed as `ssp_rk2_step`'s trailing `n_active`/`index_map` arguments — together they are what makes `ssp_rk2_step` update only real cells for *this* solver, never ghost cells (see `detail::CartesianRealCellIndexMap`'s own doc comment in `fvm_solver.hpp` for why a plain cell count alone isn't enough on a 2D/3D grid, where ghost layers interleave with real cells on every axis). |
| `cfe::SolverResidual<Solver>` | `solver/explicit/fvm_solver.hpp` | Named (namespace-scope) functor wrapping `solver->residual(in, out)` as a `residual(state_in, out)` callable for `ssp_rk2_step`. Required specifically for CUDA: nvcc forbids a *locally-defined* lambda (a closure type local to a function) as a template argument to a function whose body contains an extended `__device__` lambda — which `ssp_rk2_step` always does inside a `.cu` translation unit, regardless of which `Backend` a given call site actually selects. A namespace-scope functor sidesteps this; plain `.cpp` call sites may still use a local lambda if they will never be compiled by nvcc. |
